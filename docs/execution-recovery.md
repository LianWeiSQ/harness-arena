# 取消与检查点继续（M4）

新协议实验可以取消；控制面重启后，符合条件的中断实验可以从已确认的 Trial 边界继续。恢复不会重置预算、延长截止时间或重复执行未知业务动作。该能力适用于 `/evo` 的自动改进及人工候选评测；旧竞技赛季沿用旧协议。

## 页面与 API

运行中的实验显示“取消实验”。取消先持久化，停止接收新模型与业务动作；已发出的模型 HTTP 请求在原有超时范围内返回并结算，然后停止本题、清理其执行资源。页面直到这一过程完成才显示“已取消”。取消是终态；要重跑需新实验，不会悄悄复用一个新预算。

重启后符合条件的实验显示“从检查点继续”。API 为：

```text
POST /api/evo/experiments/{id}/cancel  body: {}
POST /api/evo/experiments/{id}/resume  body: {}, Idempotency-Key: <unique-key>
```

同一个恢复键返回原实验，不会多启动一个 Worker。不同恢复键也受单活动执行者约束。模型连接、任务包、运行代码或不可变意图发生变化时拒绝继续，要求新实验。Docker 镜像按首次执行的内容 ID 使用，标签变化不会替换镜像。浏览器关闭不会取消实验。

## 已确认的边界

1. 创建时保存不可变实验意图；领取时增加 epoch。CLI 数据目录锁维持单进程所有权，epoch 拒绝过期写入，不是多机租约。
2. 完整 Trial 的结果与内容哈希检查点在同一 SQLite 事务中落盘。继续时校验逻辑键和哈希，跳过原记录，保留原 Trial ID。
3. 模型请求先登记调用意图，响应后结算真实用量。重启时仍 pending 的请求转为 unknown；未知用量不能当作零，也不能再次请求。
4. 优化模型的原始响应先不可变保存，再解析和关联诊断/候选。若原始响应已保存而关联尚未保存，恢复会重用同一响应，不再次收费。已知收费但响应丢失时拒绝继续。
5. 判定、推荐版本 CAS、事件和控制状态在同一事务提交，并核对当前 epoch 与取消状态。项目 revision 未变化也不能绕过旧 epoch 围栏。

有未完成/未确认的 Trial、预算耗尽、绝对截止时间已过、未知调用用量或未清理资源时，恢复按钮给出拒绝理由。平台不在已有实验中删掉失败步骤、填零用量或重新派发不确定的工具动作。已确认完成但没有本协议检查点的旧实验也不直接升级为可继续状态。

## 资源所有权与对账

Harbor 启动前持久化唯一 job、Trial 工作目录及所有者 epoch。新协议使用数据目录内的 Trial 工作区，保留故障现场，目录不进入 Git。

进程对账核对唯一 job、jobs 目录、Harbor 路径和进程启动时间，确认进程组后才发送停止信号；不使用宽泛进程名。容器对账按该 Trial 的精确 host bind source 查找，删除前再次核对不可变容器 ID。业务与验收容器均采用无网络模式，没有本实验创建的 Docker 网络需要删除。无法访问 Docker 或无法确认清理结果时标为 unresolved，并拒绝下一题和恢复。

当前保证是单机控制面和 Trial 边界恢复；不恢复 Harness 内部 token 流，不自动重放未知外部副作用，不承诺磁盘损坏后的零丢失或多机接管。已发往供应商的 HTTP 请求无法靠 epoch 撤销，取消会等待它在现有超时内结束。

## 验证方法

`tests/test_recovery.py` 覆盖检查点继续、原始响应写入窗口、未知用量、已收费但响应丢失、旧执行者提交、重复恢复、取消后的模型/业务拒绝、协议变化和资源归属。所有受控记录只在临时数据库中。

`tests/manual_resource_drill.py` 是显式运行的 Docker 演练，不调用模型：创建专属容器、独立旁观容器及模拟 Harbor 进程，验证只停止归属本实验的资源。2026-11-10 实测三项均通过。

`tests/manual_recovery_drill.py` 是可能使用模型额度的独立演练，必须指定新的 `--data-dir`，禁止使用服务正在使用的数据目录。`start` 在真实 Pi/Harbor 第一题检查点提交后 SIGKILL 控制进程；`resume` 使用同一预算继续余下题目；`cancel` 在 Harbor 启动事件后一秒请求取消。参数由 `--help` 列出；该脚本不会在常规单元测试中运行。

2026-11-10 恢复演练完成 6/6 次有效 Trial，双方均通过 3/3，未宣称质量收益。总计 42 次模型请求、272,629 个已知 Token；原首题 ID、检查点和截止时间保留，6 组资源全部 cleaned。取消演练终态为 cancelled，0 次模型请求，资源 cleaned。恢复演练之后增加了启动 Harbor 子进程前的再次控制检查，取消演练已覆盖该变化；随后补齐人工评测终态提交前的取消竞态保护，并由专门故障注入测试验证。记录分别保留实测时的准确代码指纹，未把不同协议混为同一次实测。详见 [M4 验证记录](m4-verification.json)。
