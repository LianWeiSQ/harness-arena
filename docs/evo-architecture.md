## 1. 系统论点与非目标

[TARGET] Evo 接收“基线版本、任务包、允许修改范围、评测规则、预算”，生成并验证候选，输出可用版本及完整证据。核心运行单元是 Experiment，其中包含不可变版本与多次隔离 Trial。实验控制器负责推进状态，运行器执行模型与工具动作，独立判定器决定候选是否符合规则。

最难的约束是把真正生效的改动与可归因的收益连接起来，同时防止测试泄漏、无限花费和恢复时重复副作用。单机版本先保证实验级可靠性，不承诺恢复任意 Harness 内部的 Turn、Step 或模型 token 流。不提供生产部署、多租户服务或权重训练。

## 3. 边界与所有权

以下为 [TARGET]。v0.2 默认本地单用户、单执行控制面、一个活动 Trial。所有业务状态写入经 Store 事务接口，不允许 UI 直接改数据库。

| 组件 | 核心职责 | 拥有的状态 | 读取与契约 | 扩容/故障边界 |
| --- | --- | --- | --- | --- |
| API/本地 UI | 校验输入、展示状态、接收命令 | 请求幂等键 | Experiment 命令、事件游标 | UI 断开不取消实验 |
| 版本与资产库 | 固化配置和产物 | AgentVersion、manifest、内容哈希 | 加载/导入/导出接口 | 文件按哈希存储 |
| 实验控制器 | 推进计划与预算 | Experiment、Trial 意图、epoch | 领取、完成、取消、继续 | 单进程所有者锁 |
| 诊断与优化器 | 生成假设及受限候选 | Diagnosis、Proposal | 只读开发集证据 | 独立预算与超时 |
| Harness adapter | 实际加载版本并执行 | 外部进程/容器句柄、加载收据 | capability / prepare / execute / collect / cleanup | 每 Trial 隔离 |
| 独立验证与判定 | 业务验收、覆盖检查、晋升 | Evaluation、Decision | 冻结规则与产物哈希 | 不能被候选写入 |
| Store/Artifact store | 事务记录、不可变文件 | 元数据 SQLite、产物文件 | 事务、原子文件替换 | 同一本地数据目录 |

业务事实源是 SQLite 的计划与判定；业务服务的副作用事实来自测试服务账本；容器存活事实来自 Docker/Harbor 查询；UI 的分数、图表和谱系是派生结果。模型 Provider 持有其请求接受与用量事实，不能由本地“准备调用”记录代替。

## 4. 核心实体与不变量

以下为 [TARGET]。

| 实体 | 标识与版本 | 持久内容 | 唯一业务写入者 |
| --- | --- | --- | --- |
| Project | id、current_version、revision | 当前推荐版本和默认策略 | 项目命令处理器 |
| AgentVersion | id、manifest_hash、parent_id | runner/version、model snapshot、文件哈希、允许的配置 | 版本注册器；创建后不可变 |
| TaskPackVersion | id、content_hash、split_hash | 任务、分组、验证器和环境摘要 | 任务注册器；创建后不可变 |
| Experiment | id、revision、epoch | 基线、规则、候选数、预算、持久计划与终态 | 实验控制器 |
| Trial | id、experiment、version、case、repeat、attempt | 意图、状态、环境、加载收据、用量、验证结果引用 | 控制器接收当前 epoch 的结果 |
| Diagnosis/Proposal | id、input_hash、parent_id | 事件引用、假设、diff、修改范围、生成调用 | 诊断与候选服务 |
| Evaluation/Decision | id、protocol_hash、coverage_hash | 配对记录、理由、接受/拒绝/证据不足 | 判定器，经 Store 事务落库 |
| EffectReceipt/Artifact | id、trial_id、hash | 外部接受证据或文件位置、来源、脱敏状态 | 收集器；记录追加 |

不变量：候选内容与实际加载哈希一致；同一 Trial 不复用前一 Trial 的工作区和记忆；任务与评分规则在实验内冻结；不完整配对不能晋升；没有 Decision 不改推荐版本；推荐版本 CAS、Decision 与事件同事务提交；预算统计包含诊断、候选生成、失败和重试；秘密值不进入版本包和导出。

## 5. 接口与协议契约

以下为 [TARGET]，路由名是实现草案。

| 接口 | 成功语义 | 校验与幂等 | 错误语义 |
| --- | --- | --- | --- |
| `POST /api/evo/versions` | 201，版本已固化 | schema、内容哈希、路径白名单、能力检查 | 不支持的修改维度拒绝 |
| `POST /api/evo/experiments` | 202，计划已持久化 | 项目+Idempotency-Key+payload_hash，同事务保存请求与实验 | 同 key 不同 payload 为 409 |
| `POST .../cancel` | 已记录停止意图 | expected_revision | 已终态返回原结果 |
| `POST .../resume` | 新 epoch 的剩余计划已入队 | 可恢复状态、旧进程对账、剩余预算 | 未知副作用未解决则不能继续该步骤 |
| `GET .../events?after=` | 游标后的持久事件 | 单调 seq，分页 | 重连仅回放事件，不再次调用模型 |
| `POST .../promote` | 本地推荐版本切换已提交 | 完整 Decision、expected_version/revision | 陈旧结果为 409 |
| `POST .../export` | 导出指定哈希的脱敏产物 | 固定版本与审计清单 | 泄露检查失败不导出 |

模型配置保存身份与 credential reference，版本与实验不复制秘密值；修改默认连接不改变既有实验的模型快照。凭据轮换只更新秘密来源，Provider 身份、模型和参数变化则需要新实验。旧 `/api/harness` 与 FixOps 路由保留。

## 6. 正常关键链路

以下为 [TARGET]。

1. API 校验运行器能力、版本、任务包、规则与预算，事务保存请求和实验计划。202 表示接收，不表示执行成功。
2. 控制器持久化 Trial 意图及预算预留，再创建隔离环境。版本包只包含本实验允许的资产。
3. adapter 记录实际加载文件、运行器/镜像版本与 manifest 哈希。哈希或能力不匹配直接停止该 Trial。
4. 执行 Harness，宿主网关记录模型调用和业务工具收据。原始敏感信息在进入公开事件前脱敏。
5. 冻结产物，独立验证器读取目标业务状态或结果文件，产生版本化 Evaluation；结果及产物哈希落库。
6. 诊断器读取开发集证据，优化器生成受限 patch，先校验再创建不可变候选；其调用也计入预算。
7. 父本和候选按冻结计划配对执行。判定器核查完整性、回归和规则，事务提交 Decision；接受时用 CAS 更新项目推荐版本。
8. 运行封存报告，展示完整结果与局限，导出版本包和证据。终止与取消经过相同的资源清理路径。

第一个持久点是实验计划，外部副作用提交点在 Provider/业务工具，最终接受证据是 Decision 事务。UI 只观察这些事实，不拥有执行生命周期。

## 7. 状态机与持久化

以下为 [TARGET]。实验从 `queued` 到 `running`，阶段单独使用 `baseline/diagnosing/proposing/validating/reporting`；业务阶段与调度状态分离。

| 状态 | 进入/退出 | 驻留与恢复 | 终态 |
| --- | --- | --- | --- |
| queued | 计划已提交；控制器领取后 running | 启动扫描可重新领取 | 否 |
| running | 持有当前 epoch；按持久阶段推进 | 受实验 Deadline、心跳和预算限制 | 否 |
| cancelling | 收到取消意图；停止新派发并清理 | 核对进程和调用，再落 cancelled | 否 |
| interrupted | 所有者丢失或运行中断 | 对账后显式继续生成新 epoch | 否 |
| needs_reconciliation | 外部操作结果未知 | 查询 receipt；无法核实时保留待处理 | 否 |
| completed | 计划全部完成 | 候选可接受也可全部拒绝 | 是 |
| budget_exhausted / cancelled / failed | 上限到达、取消完成、不可恢复故障 | 保留已完成结果，新预算需新实验 | 是 |

Trial 使用 queued/running/verifying/passed/failed/error/interrupted；重试创建新 attempt，旧记录不改成未执行。诊断和生成的结果也有独立检查点。产物先写临时文件、校验并原子更名，再提交数据库引用；未引用文件可回收。

没有任务等待输入的产品需求时不新增 Approval 等待流程。后续确需 Approval，保存参数哈希、决策者和有效期；等待释放执行资源，不能只用内存 channel。

## 8. 并发、幂等与一致性

[FACT] 当前通过 `cli.py:19` 的目录所有者锁限制控制面，`web.py:49` 用线程执行长任务。[TARGET] v0.2 延续单所有者，新增数据库状态 CAS 和 epoch，重启与旧进程对账后才能推进。

请求唯一键为 `(project_id, idempotency_key)`，Trial 逻辑键为 `(experiment_id, phase, version_id, case_id, repeat_index, attempt)`。状态转换同时校验 revision/epoch。计划、事件、请求记录在必要事务中一起提交，解决接收后丢响应重试问题。终态幂等返回原结果。

旧 Worker 的结果即使迟到，也只能作为过期证据保存，不可覆盖新 epoch 状态。围栏阻止状态写入，不能撤销已经发给外部服务的动作；工具本身还需幂等键或核对接口。v0.2 不实现多机租约；需要多 Worker 时再增加 lease_owner、lease_expiry、心跳和数据库领取协议。

## 11. 安全与隔离

[TARGET] 默认仅监听回环地址，延续同源写入限制；未来暴露远端需要另外设计身份与授权。运行器只能读其版本包与任务工作区，不能读取宿主凭据、验证器答案、其他实验记忆或 Docker 管理接口。

候选 patch 限定文件类型、相对路径、大小和 schema，防止 `..`、绝对路径、符号链接越界。默认只开放文本策略/Skill 与允许配置，工具代码或 Harness 源码变更放入后续独立隔离和测试路径。权限规则与评分器不属于候选可改范围。

原始轨迹可能含业务内容或凭证，导出必须按白名单字段与脱敏规则生成新产物，保留来源摘要。删除模型连接不能使旧导出出现密钥。对抗样本覆盖提示注入、读取验收文件、污染记忆和篡改产物。容器隔离不等同于强多租户隔离，v0.2 不承担公共不可信租户运行。

## 12. 性能、容量与成本模型

[TARGET] 单 Trial 并发为 1。到达率 λ、平均服务时长 W 与平均并发满足 `L ≈ λW`；当 λW 接近 1 时排队增大，以队列长度和模型配额拒绝/延迟新实验。主要耗时拆为镜像准备、排队、模型等待、工具执行、验收和产物保存，分别记录，避免把冷启动误认为 Harness 性能。

设开发实例 D、验证实例 V、封存实例 H、候选数 K、重复次数 R。保守全量执行预算为 `N = D + 2*K*V*R + 2*H*R` 个 Trial；另加诊断/生成调用和反馈消融对照。共享不变父本结果只能在协议事先允许且指纹相同时复用。

## 18. 面试三级追问题库

### Q1 为什么需要版本和加载收据

**一级追问：**保存一段新提示词就算进化了吗？

**主回答：**不够。目标机制要求 AgentVersion 的 manifest 哈希与 adapter 实际加载内容一致，才能把结果归到该候选。当前 Pi 禁用自动 skills 的代码正说明注册文件不等于执行生效；M1 用两份不同版本的真实加载测试证明。

**二级追问：**具体存什么？

**二级回答：**版本存文件哈希、配置、运行器和模型身份，Trial 存加载收据、镜像和任务版本。诊断引用 Trial 事件，判定引用 Evaluation，不能只依赖显示名称。

**三级追问：**文件被改了或旧结果迟到怎么办？

**三级回答：**内容寻址与加载校验拒绝不一致，控制器用 epoch 拒绝旧结果写终态；这些是目标机制，待集成和迟到写入测试证明。

### Q2 怎样证明新版更好

**一级追问：**一次成功够吗？

**主回答：**不够。目标协议冻结任务、模型和预算，父子配对重复运行，检查回归，并用封存集报告选择后的结果。小样本仍只证明有限任务上的表现。

**二级追问：**如何防止只学会答案？

**二级回答：**候选生成只读开发集，按模板/机制分组，独立验收不可修改；记录原始基线与移除反馈的等预算对照。

**三级追问：**试了很多候选会不会碰巧选中一个？

**三级回答：**会有选择偏差。固定搜索预算、保留全部候选、使用未参与选择的封存集，并披露重复数、原始结果和缺失覆盖；不能把一次选中当成普遍提升。

### Q3 重启怎样避免重复执行

**一级追问：**为什么不从头再跑？

**主回答：**模型可能已计费，业务工具可能已提交。目标恢复从持久 Trial 边界推进，先核对外部证据。当前实现仅标中断，M4 才新增继续语义。

**二级追问：**检查点和事务在哪里？

**二级回答：**外部动作前保存意图，动作后保存 Receipt；晋升指针、Decision 和事件同事务提交。重试使用新 attempt，已经确认的结果保持不变。

**三级追问：**对端成功但没有可查收据怎么办？

**三级回答：**记录未知结果并停止该步骤自动重放，不能声称 exactly-once。业务任务优先提供查询接口，Provider 未知用量保留预算风险；用丢回包测试验证。
