# 面试演示与可证明的技术边界

项目主线是 Harness 自改进：把实际执行反馈变成有证据的改动，再验证是否值得采用。围绕一个具体实验解释“改了什么、为什么改、实际加载了什么、怎样判定、失败后怎么办”。竞技页是历史原型。

## 五分钟演示

| 时间 | 页面与动作 | 要讲清的事实 |
| --- | --- | --- |
| 0:00–0:45 | 总览或真实案例回放 | 本例生成了 Skill，但只有 10/24 次有效验证，结论为证据不足；回放不写本地历史 |
| 0:45–1:30 | 版本文件和父子关系 | 文件、运行器、模型身份形成不可变版本，执行有加载哈希及请求输入证据 |
| 1:30–2:30 | 诊断与 diff | 引用开发 Trial，只改授权文件；模型输出不直接成为已采用版本 |
| 2:30–3:30 | 逐题结果与运行证据 | 覆盖先于分数，同题重复配对；独立验收，执行错误不等于策略失败 |
| 3:30–4:15 | 预算和恢复说明 | 未知用量保留，已提交 Trial 不重跑，未知副作用不自动重放 |
| 4:15–5:00 | 导出与推荐历史 | 产物可以复用；采用和回滚是本地指针事务，不改历史，不等于外部部署 |

网络不稳定时用保存的实验或只读案例并明确标注，不要把模拟接受判定混入真实实验库。完整真实协议和对照报告状态以 [TASKS.md](../TASKS.md) 为准。

## 能经得住追问的设计

**怎么证明 Skill 生效？** 版本哈希、容器文件核对和实际模型输入相互关联。进入目录只是注册；`skill_contents_in_input` 另记正文读取。读过也不保证遵循，最终仍要独立验收。

**为什么不能只看总通过率？** 缺失结果、环境错配或供应商异常会破坏配对。先验证覆盖、签名、冻结与输入，再逐题检查回归，要求总成功数严格增加且无关键违规。Token 节省不替代质量门槛，小规模结果不宣称统计显著。

**崩溃后怎么续跑？** 完成的 Trial 与检查点同事务保存。恢复递增 epoch、核对资源和总账，显式继续剩余计划，保留原截止时间。M4 实测在首题提交后 SIGKILL，恢复完成其余五题，没有重跑首题。未确认请求记为未知并停止；不保证供应商请求 exactly-once。

**迟到实验会覆盖回滚吗？** 推荐变更要求版本和修订号匹配，执行提交还需当前 epoch。回滚递增修订号，旧实验后来通过也不能覆盖它。Decision、指针和事件在同一 SQLite 事务提交，失败整体回滚。

**验收器会被 Agent 修改吗？** 真值和签名密钥在宿主侧，Agent 不挂载验证脚本和账本；独立验证容器只读核对。宿主还核对签名、冻结、reward 和 checks。该隔离面向可信本机控制面下的任务执行，不宣称抵抗宿主管理员。

**为什么使用 Harbor？** 它承担任务容器生命周期和结果收集，Evo 负责版本、预算、优化和准入。固定版本与适配器减少重写工作，也带来依赖体积与兼容成本。Harbor 是可选安装，基础浏览不需要它。

## 简历描述与边界

可写：“开发基于 Harbor 的 Harness 自改进实验平台，集成 DSH/Pi，支持不可变版本、证据驱动的候选生成、配对评测、实验预算、幂等提交、检查点恢复与审计回滚。”

可量化证据包括 3 类业务机制、18 个场景、开发/验证/封存分组，以及 [M4 演练](m4-verification.json) 和 [M5 验收](m5-verification.json)。测试数量以当前 CI 和阶段记录为准。

当前不能写“自动进化已显著提高成功率”“支持模型权重训练”“实现分布式 Worker 自动接管”或“生产级多租户”。完整 M3、封存与等搜索预算对照未完成时必须保留边界。旧 FixOps 记录见 [首场实验](first-experiment.md)，不混同新协议结果。
