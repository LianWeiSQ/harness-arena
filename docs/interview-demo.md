## 可以深入讨论的实现

版本注册使用内容摘要和不可变记录；每次执行记录策略和完整协议输入摘要。候选修改不会覆盖原版，席位记录指向具体版本。

晋级在 SQLite 单个事务中比较席位版本、替换席位、保存决定和事件。相同决定重试不会再次晋级，旧席位写入会被拒绝。HTTP 创建赛季的幂等键避免网络重试启动第二场付费比赛。

验证器运行于控制面，Agent 不获得测试实现或 Docker 管理权限。真正的环境里运行网关和订单服务；受限配置工具只允许修改业务上游，并确认容器观察到写入结果。故障环境和健康环境在模型执行前都要校准。

预算按实际供应商用量累计。模型 HTTP 或传输异常、缺少用量时保留未知并停止继续派发；它们不能计为策略回归。用户取消时，正在进行的模型请求返回后，在下一项工具副作用之前再次检查取消状态。

进程丢失后的运行被标为 interrupted，清理已知的受管容器。重启可以继续浏览原始记录，但当前版本不自动接管运行，也不自动重放不确定动作。

## 当前结论和后续实验

首版已经证明执行和进化闭环能够工作，还没有证明进化机制带来收益。任务只有一个故障族，三组端口变体不足以证明跨故障泛化。比较耗时也受到模型服务和本地 amd64 模拟执行的影响。

后续优先增加更难的故障族、每类多个实例和重复实验；比较固定初始策略与等搜索预算但不使用失败反馈的候选生成方式。再考虑接入 OpenHarness 和 BrainBox。不能把这些后续能力写成已实现的简历成果。

简历可以描述已实现的受限 Agent 运行平台、内容版本、幂等和晋级事务、独立评测及可追查进化。具体数字采用真实报告中的样本量、请求数和用量，不预设成功率提升。
