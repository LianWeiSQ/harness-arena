# 一次自动改进实验（M3）

自动改进模式将开发基线、模型诊断、受限文件生成、真实 Harness 执行和配对验证放到同一个实验预算内。M3 是单候选闭环；取消与检查点继续见 [中断恢复](execution-recovery.md)，持续搜索仍按 TASKS.md 推进。

## 操作

1. 在 `/evo` 选择基线。没有基线时，先配置模型，再创建包含策略或 Skill 的版本。
2. 实验方式选“自动改进”，明确允许修改的一个现有文件。Pi 可选择策略或原生 Skill，DSH 当前只能选择策略。
3. 选择诊断/生成模型连接和总预算。执行模型沿用基线，生成模型可以独立选择；启动后两者都使用当时解析的连接快照。
4. 点击“开始改进实验”，观察开发基线、诊断、候选、验证、判定五个阶段。
5. 查看“为什么这样改”中的观察、证据引用和假设，再检查文件 diff 与验证成绩。点击证据 ID 可跳到对应 Trial；引用存在不代表模型的解释必然正确。

每次计划固定为 6 次开发基线执行、最多 2 次诊断调用（含 1 次结构修正）、1 次候选生成调用、24 次验证执行（6 题 × 2 次 × 两个版本）。每个 Harness Trial 最多 12 次模型调用，因此默认总请求上限为 363，Token 上限 300 万，总时限 4 小时。预算可以在启动前调低；不足时记录缺失覆盖，不能据此晋升。

通过 API 创建同样的实验：

```json
{
  "mode": "improve",
  "baseline": "已保存的基线版本 ID",
  "target": "skills/order-recovery/SKILL.md",
  "optimizer_profile": "已配置的模型连接 ID",
  "limits": {"calls": 363, "tokens": 3000000, "seconds": 14400}
}
```

提交到 `POST /api/evo/experiments`，沿用 `X-EvoArena-Request: 1` 和 `Idempotency-Key`。可传已有 `project`；基线必须是该项目当前推荐版本。第一次改进会创建项目并冻结初始版本。候选被拒绝时，初始版本和推荐指针都保留。

## 信息隔离和候选权限

诊断输入只由完整的开发集结果构造：公开任务要求、基线文件、逐项验收、真实用量和限长轨迹片段。事件使用 `E0001` 等短引用，明确映射到 Trial ID 与事件序号；独立结果也有可追溯的短引用。验证与封存的任务细节、答案、轨迹，以及模型端点和凭据不进入这份输入。

诊断必须输出有来源的观察、引用观察的假设、授权目标、预期影响和验证方式。每条观察只能引用 1–12 条已提供证据。原始模型输出先写入不可变记录，再做校验；不存在的证据、错误结构或越界目标触发最多一次预算内修正，仍不合法则拒绝继续。假设可以涉及已经成功任务中的脆弱点，但不能把“可能有问题”显示为已证实的故障。

候选生成只接收诊断、授权文件、其他基线文件和被引用的开发证据。返回值只能包含名称、一个文件的完整内容和改动理由。平台固定模型、运行器、父版本和文件路径，其余文件逐字保留；Skill 的 frontmatter 在校验后规范化为带引号的 name/description，正文保留，页面展示实际落盘的 diff。没有实际变化的输出不创建候选版本。

生成文件使用正常版本加载链路，核对文件哈希、运行器版本及实际模型输入。诊断模型不会运行修改后的资产，也没有修改本次评分器、任务或业务账本的接口。

## 判定与推荐版本

验证计划的任务、分组、重复次数、顺序、预算和质量规则在生成候选前固定。生成后只将候选占位符绑定为不可变版本 ID；判定前重新核对绑定后的计划是否与预声明模板一致。

质量规则沿用 M2：24 次有效覆盖完整，各题候选成功次数不低于基线、总成功数严格增加，候选关键约束零违反。节省 Token 不会代替质量门槛；该规则不表示统计显著性。封存报告和同搜索预算反馈消融仍在 M6 完成。

判定区分接受、拒绝、证据不足以及“推荐版本已变化，未应用”。无收益、退化、非法候选、预算耗尽、模型错误等原因独立记录。接受仅更新本地项目推荐指针，不部署外部服务。

推荐版本 CAS、不可变 Decision、实验终态和事件在同一 SQLite 事务提交。提交失败整体回滚；相同 Decision 再次提交返回原结果。即使质量提高，项目当前版本或 revision 已变化时也不能覆盖新状态。M4 增加了当前执行 epoch 与取消状态校验，旧执行者不能提交判定或更新推荐版本。

诊断、生成和 Harness 执行都进入同一个持久预算总账。响应缺失用量或派发后中断时保留未知，不算成零成本，也不自动重试。

## 验证范围

`python -m unittest discover -s tests -p test_improvement.py -v` 覆盖受控测试中的接受、无收益拒绝、逐题退化、越界候选、预算停止、证据隔离、错误引用、协议篡改、陈旧推荐版本、事务回滚和重复提交。测试中的模拟执行不写入用户实验历史。

真实实验保存在 `.evoarena/experiments/` 和本地数据库。第一场集成实验在诊断引用校验时被拒绝，没有候选或推荐版本变更；当时尚未保存原始响应，因此不能事后断言具体引用错误。当前实现已补齐原始响应、明确引用数量上限、短引用映射和预算内一次结构修正。

第二场 `ex-8163f70dac1d` 已由真实模型生成 Skill，实际加载后取得 10/24 次有效验证结果；后续一次模型请求的响应异常且用量无法确认，实验在 2026-11-10 16:43（北京时间）以证据不足结束，没有更新推荐版本。旧版判定记录的原因为 `incomplete_coverage`，运行记录保留供应商异常；M4 将这类新实验原因细分为 `execution_error`，不改写历史 Decision。134 次请求、902,450 个已知 Token 和 1 次未知用量均保留。完整协议验收仍未完成，不用部分通过率或受控测试代替。脱敏记录见 [M3 集成记录](m3-verification.json)。
