# EvoArena 观战体验与下一版方案

界面沿用 EvoTrader Arena 的指标栏、主图、动态侧栏和排行榜布局。首屏直接给出故障和策略成绩。订单请求返回 502，网关指向错误的上游。两个 Agent 使用同一模型和动作预算，各自在独立环境中尝试恢复业务。下单、查单和依赖检查由验收程序执行。

## 观战顺序

| 用户想知道什么 | 页面给出的答案 |
| --- | --- |
| 要解决什么问题 | 顶部的 HTTP 502 场景标记和主图中的故障描述 |
| 哪个策略修好了 | 主图显示每轮耗时或 Token 用量，排行榜按轮显示名次和验收结果 |
| 新版是否有进步 | 原版和新版并排显示通过数，晋级结论放在策略差异前 |
| 它实际做了什么 | 点图例或排行榜选中策略，在右栏切换执行、验收和进化 |
| 换个端口还行吗 | 所有轮次结束后展示独立复测结果 |

界面把一次完整运行称为「一次对比」。默认两轮。第一轮比较起始策略，随后生成并检验一个改进版。第二轮使用保留的策略再次比较。复测最后进行。第三轮会多一次改进机会。历史按开始时间选择，策略数、轮数和模型请求预算放进启动窗口。

现有记录的父子版本都各通过一项，页面明确解释下一轮沿用原有策略。耗时差异只影响本轮展示顺序。现有单故障、单样本条件不足以评价进化收益。

## 下一版优先级

1. **让故障能区分策略。** 在现有上游地址错误之外，加入需要不同诊断和修复动作的场景，例如路径改写错误和上游超时。每个场景附故障注入、正常验收和错误修复用例，先验证环境可重复。
2. **让新版结果可比较。** 原版和新版在同一批测试实例上配对，并重复运行。报告逐实例通过数、退化样本、调用次数与覆盖率，再对照固定初始策略和相同搜索预算下的候选生成结果。
3. **让演示容易复现。** 提供一份脱敏的真实运行回放和一条启动命令。观众可先从故障描述跳到一次修复和一次晋级判定，有模型配置时再发起真实对比。

验收时用三个问题检查信息是否传达清楚。用户能否说出故障是什么、两轮之间发生了什么，以及为什么某个新版没有晋级。实验侧先检查失败可复现、父子覆盖一致、结果可回查，再解释通过率变化。
